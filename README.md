# Timio

Backend: **Hono.js + PostgreSQL + Redis**.
Frontend: **Nuxt 4 + Vue 3 + TypeScript + Pinia + TailwindCSS**.

Полноценный флоу продукта, а не демо одного бизнеса:

> Любой пользователь регистрируется → создаёт СВОЮ компанию (URL генерируется
> автоматически из названия) → добавляет СВОИ услуги, цены и сотрудников →
> получает публичную страницу записи и панель управления.
>
> На публичной странице язык клиента определяется автоматически
> (`Accept-Language` браузера / Telegram `language_code`) — владелец бизнеса
> его не выбирает. Английский клиент может записаться к русскоязычному
> мастеру: увидит интерфейс и получит уведомление на английском.

## Запуск (одной командой через Docker)

```bash
cd timio
docker compose up --build
```

- Frontend: http://localhost:3000
- API: http://localhost:8787

При первом старте контейнер `api` автоматически применит схему к Postgres и
опционально заведёт демо-бизнес `demo-barbershop` (логин `demo@timio.app` / `demo12345`)
— это не обязательный шаг продукта, просто быстрый способ посмотреть публичную
страницу без прохождения регистрации.

## Запуск без Docker (по отдельности)

```bash
# Postgres + Redis нужны локально (или см. docker-compose.yml сервисы postgres/redis)

cd timio/api
cp .env.example .env
npm install
npm run db:push
npm run db:seed      # опционально - демо-бизнес
npm run dev           # http://localhost:8787

# в другом терминале
cd timio/web
npm install
npm run dev            # http://localhost:3000
```

## Как это выглядит для реального пользователя

1. Открывает `/` → жмёт «Создать компанию бесплатно».
2. Регистрируется (`/register`) — email, имя, пароль.
3. Онбординг (`/onboarding`): вводит название компании (URL генерируется
   автоматически, например «Салон красоты Мария» → `timio.app/salon-krasoty-mariya`),
   выбирает сферу деятельности, добавляет свои услуги с ценами и длительностью,
   опционально добавляет сотрудника.
4. Попадает в панель управления (`/app/:businessId`): обзор, записи, услуги,
   сотрудники — всё только своё.
5. Делится ссылкой на публичную страницу. Клиент открывает её в браузере на
   любом языке — видит услуги, мастеров и уведомление о записи на своём языке.

## Что реально работает и было протестировано

- ✅ Регистрация/вход владельца с JWT (`scrypt`-хэш пароля, токен на 7 дней)
- ✅ Создание бизнеса с автогенерацией уникального URL из названия (включая транслитерацию кириллицы)
- ✅ Индивидуальные услуги и сотрудники на каждый бизнес (не общий каталог), с фото (загрузка изображений)
- ✅ Публичная запись: выбор услуги → мастера → **даты** (лента на 14 дней) → времени, с кнопкой **«назад»** на каждом шаге
- ✅ Индивидуальное окно приёма для каждого сотрудника (отдельно от расписания бизнеса по умолчанию), с проверенным сбросом Redis-кэша при изменении
- ✅ Переключатель **светлой/тёмной темы** (сохраняется в localStorage), применяется на публичной странице и в дашборде
- ✅ Раздел **«Аналитика»**: выручка, налог (настраиваемый %), комиссии сотрудников (настраиваемые % на каждого), чистая прибыль — с графиками по дням/услугам/сотрудникам
- ✅ Скачивание отчёта в **.xlsx** (SheetJS, генерируется в браузере, 5 листов: сводка/по дням/по услугам/по сотрудникам/все записи) — протестирован расчёт: выручка 1500 ₽, налог 15% = 225 ₽, комиссия сотрудника 40% = 600 ₽, чистая прибыль = 675 ₽
- ✅ Ролевая модель на уровне БД (`business_members`: owner/administrator/manager/employee), проверка владения на каждом `/me/*` роуте
- ✅ Дефолтные мультиязычные шаблоны уведомлений создаются автоматически при регистрации бизнеса
- ✅ PostgreSQL как основное хранилище, Redis — кэш доступности + очередь напоминаний
- ✅ Автоопределение языка клиента на публичной странице и в уведомлении о записи (владелец бизнеса язык не выбирает)
- ✅ Прод-сборка Nuxt (`nuxt build`) проходит без ошибок, все страницы отдают 200
- ✅ Единая дизайн-система (светлая/тёмная тема, красный акцент, Roboto) на всех экранах: лендинг, auth, онбординг, дашборд, публичная запись

## Осознанные упрощения (следующий шаг)

- Реальная отправка в Telegram/WhatsApp/SMS не подключена — уведомление
  логируется в `notification_logs` с указанием канала и текста. В проде на
  этом месте BullMQ-воркер, читающий Redis-очередь `reminders:scheduled`.
- Названия услуг при создании кладутся владельцем на одном языке во все 7
  языковых слотов сразу (чтобы клиент никогда не видел пустоту); ручной
  перевод/редактирование по языкам — следующий экран в панели.
- Фото хранятся как data-URL прямо в базе (без отдельного объектного
  хранилища) — работает для MVP, но не подходит для продакшена с большим
  количеством изображений; следующий шаг — S3/CDN.
- Календарь с drag&drop, редактирование/перенос существующих записей
  администратором, полноценная CRM-карточка клиента (история, заметки,
  теги) — контракт данных готов (`appointments`, `clients`), экраны ещё не построены.
- Роли Administrator/Manager/Employee: приглашение сотрудников в аккаунт
  (сейчас есть только Owner при регистрации бизнеса).

## Переменные окружения

```
DATABASE_URL=postgres://postgres:postgres@localhost:5432/timio
REDIS_URL=redis://localhost:6379
PORT=8787
JWT_SECRET=change-me-in-production
```

`web` — `NUXT_PUBLIC_API_BASE` (адрес backend API, по умолчанию `http://localhost:8787`).
